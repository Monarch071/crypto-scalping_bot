# План запуска на Binance 28 октября 2026

Две разные проверки:

* **«Бот работает правильно»** можно ускорить и закончить к 28-му (шаги 1–4).
* **«Стратегия зарабатывает»** ускорить нельзя: это покажет только будущее. Поэтому 28-го запускается
  **маленькая сумма с жёстким потолком**, которую не жалко потерять целиком, и она растёт только по правилам
  шага 6.

## Что уже проверено (в облаке, 21 октября)

* 28 автотестов: стратегия, план ордеров, бумажный счёт, стоп по просадке, потолок капитала, выход из рынка,
  пропуск при несвежих данных, журнал после перезапуска.
* Бэктест бота совпадает с исследованием (+88.5% в год за 2022–2025 у обоих).
* **Живой код бота прогнан по истории час за часом**: 2022 — октябрь 2026, 1000 → 13 909 USDT,
  максимальная просадка 49.5%; 2026 год: −3.5%. Векторный бэктест того же периода близок
  (расхождение объясняется полосой ребаланса).
* Найдено и исправлено: стоп по просадке 35% сработал бы в мае 2025 года на обычных колебаниях
  и зафиксировал −25% вместо +42%. Стоп поднят до 55% (за пределами всей истории), а размер риска
  задаётся потолком капитала.

## Шаги на вашем компьютере

### 1. 21–22 октября: установка и проверка на всём рынке (главная проверка стратегии)

```bash
git clone https://github.com/Monarch071/crypto-scalping_bot && cd crypto-scalping_bot
git checkout claude/crypto-scalping-bot-weak-laptop-gy7vh2
pip install -r requirements.txt
python -m pytest -q                                   # должно быть 28 passed

# Все USDT-пары, которые когда-либо были на Binance, включая исключённые (несколько часов загрузки)
python research/download_binance.py --all-usdt --market spot --interval 1h \
    --start 2020-01 --end 2026-09 --panel data/panel_all_1h.parquet
python rotate.py backtest data/panel_all_1h.parquet --cost-bps 15
python rotate.py replay data/panel_all_1h.parquet --start 2022-01-01
```

**Критерий:** на всём рынке (с мёртвыми монетами) бэктест 2022–2025 должен оставаться заметно лучше
«купил и держи» BTC, а максимальная просадка не больше 55%. Если результат развалился, значит, хорошие цифры
давала ошибка выжившего, и **реальные деньги не запускать**.

### 2. 22–24 октября: Binance Testnet в ускоренном режиме (механика ордеров)

1. Ключи на https://testnet.binance.vision (вход через GitHub).
2. `rotation.toml`: `mode = "live"`, `testnet = true`, `rebalance_h = 1`, `max_capital_usdt = 1000`.
3. `BOT_API_KEY=... BOT_API_SECRET=... python rotate.py -c rotation.toml run --live`
4. 24–48 часов: каждый час бот перекладывает портфель (как за 8 дней в обычном режиме).

**Критерий:** нет ошибок ордеров, в журнале (`status`) покупки и продажи с разумными ценами,
после `Ctrl+C` и перезапуска бот помнит позиции, `/kill` в Telegram продаёт всё.
Цены testnet ненастоящие: здесь проверяется только механика, не прибыль.

### 3. 23–27 октября: paper на настоящих ценах Binance

Параллельно с testnet: `mode = "paper"`, `testnet = false`, `rebalance_h = 8`, `state_file = "data/paper.json"`.
Проверяется, что сигналы на реальном рынке выглядят разумно и бот не падает сутками.

### 4. 27 октября: реальный ключ и предстартовая проверка

1. Ключ API на Binance: **только спотовая торговля, вывод запрещён, привязка к IP** компьютера или VPS.
   Лучше отдельный субаккаунт.
2. `rotation.toml`: `mode = "live"`, `testnet = false`, `rebalance_h = 8`, `max_capital_usdt = <сумма>`,
   новый `state_file = "data/live.json"`.
3. `python rotate.py -c rotation.toml preflight`. Все пункты должны быть ✅.

### 5. 28 октября: запуск

`python rotate.py -c rotation.toml run --live` на машине, которая работает круглосуточно (лучше VPS:
ноутбук засыпает). Бот начнёт с ближайшего пересмотра (00:00, 08:00 или 16:00 UTC). Если BTC в этот момент
ниже своей средней за 30 дней, бот честно останется в USDT. Это часть стратегии, а не ошибка.

**Сумма:** только та, которую не жалко потерять полностью. Историческая просадка стратегии почти 50%.

### 6. Правила увеличения суммы

* Не раньше чем через 4 недели и не меньше 60 сделок.
* Реальное исполнение совпадает с ожиданием: средняя комиссия и проскальзывание не больше 0.2% за сделку,
  нет пропущенных пересмотров и ошибок.
* Результат бота за период не хуже, чем у `rotate.py replay` на тех же неделях (его можно прогнать после
  догрузки данных).
* Увеличивать не больше чем вдвое за раз.

### Когда остановить сразу

Повторяющиеся ошибки ордеров; бот держит монету, которой нет в цели; расхождение баланса с журналом;
срабатывание стопа по просадке. В Telegram: `/kill`.
