# crypto-scalping_bot

Скальпинг-бот для криптовалют, устроенный по той же схеме, что и системы
профессиональных маркет-мейкеров, но в масштабе, который тянет слабый ноутбук
(около 35 МБ памяти, один поток).

## Что взято у крупных компаний

| Компонент | Что делает |
|---|---|
| **Событийный движок** | Один и тот же код работает в бэктесте, paper и live. Нет «бэктест-версии» стратегии, которая ведёт себя иначе, чем боевая. |
| **Маркет-мейкинг (Авелланеда–Стойков)** | Бот не угадывает направление, а стоит лимитными ордерами с двух сторон и зарабатывает на спреде, платя низкую мейкерскую комиссию. |
| **Microprice** | Справедливая цена с учётом объёмов в стакане, а не просто середина спреда. |
| **Управление инвентарём** | Чем больше позиция, тем сильнее котировки смещаются в сторону её закрытия. |
| **Сигналы микроструктуры** | Дисбаланс стакана и потока агрессивных сделок слегка сдвигают котировки. |
| **Защита от токсичного рынка** | При всплеске волатильности или широком спреде котировки снимаются. |
| **Pre-trade риск** | Каждый ордер проверяется: лимит позиции с учётом рабочих ордеров, размер, fat-finger, частота ордеров, свежесть данных. |
| **Kill switch** | Дневной лимит убытка или команда `/kill`: снять все ордера и закрыть позицию. |
| **OMS** | Жизненный цикл каждого ордера; новые ордера не ставятся, пока биржа не подтвердила отмену старых. |
| **Реалистичный симулятор** | Задержка сети, post-only, очередь в стакане (касание цены не исполняет), объём сделок, комиссии. |
| **Запись данных** | Свой архив маркет-даты для бэктестов. |
| **Telegram** | Уведомления и команды `/status`, `/kill`, `/resume` (только из вашего чата). |

## Чего здесь нет и быть не может

Крупные фирмы зарабатывают за счёт того, что домашнему боту недоступно:
серверов рядом с биржей (задержка ~1 мс против 30–150 мс из дома), VIP-комиссий
(иногда отрицательных, то есть биржа доплачивает), прямого доступа к бирже,
кода на C++/FPGA и команд исследователей. **Архитектуру можно повторить,
преимущество в скорости — нет.** Поэтому стратегия рассчитана на спред в
несколько базисных пунктов, а не на гонку за первое место в очереди.

## Быстрый старт

```bash
pip install -r requirements.txt
python -m pytest -q                                  # тесты
python main.py backtest --synthetic --hours 24       # прогон на синтетике
```

Порядок перехода к реальным деньгам:

1. **Запишите настоящие данные** (лучше несколько дней, с VPS):
   `python main.py record --minutes 1440 --out data/btc_day1.jsonl.gz`
2. **Бэктест на них**: `python main.py backtest --data data/btc_day1.jsonl.gz`.
   Подбирайте параметры на одних днях, проверяйте на других.
3. **Paper trading** на живых данных минимум 2–4 недели:
   `cp config.example.toml config.toml && python main.py -c config.toml run`
4. **Testnet с ключами** (`mode = "live"`, `testnet = true`):
   `python main.py -c config.toml run --live`
5. Только потом `testnet = false` и минимальный депозит.

Секреты задаются переменными окружения:

```bash
export BOT_API_KEY=...        # ключ API без права вывода средств!
export BOT_API_SECRET=...
export TELEGRAM_BOT_TOKEN=... # от @BotFather
export TELEGRAM_CHAT_ID=...   # ваш chat id
```

## Важно

* Модуль `scalper/gateways/live.py` ещё не проверялся на настоящей бирже.
  Сначала testnet.
* На синтетических данных со скачками цены стратегия **убыточна**: её
  «пробивают» резкие движения (adverse selection), и съедают комиссии. Это
  нормально и честно показывает главную проблему маркет-мейкинга. Прибыльность
  зависит от параметров, пары и комиссий, и проверять её можно только на
  реальных данных.
* Ставьте API-ключу запрет на вывод средств и привязку к IP.
* Для работы 24/7 используйте VPS рядом с биржей, а не ноутбук.

## Структура

```
main.py                  CLI: run / record / backtest
scalper/engine.py        движок: события → стратегия → риск → OMS → шлюз
scalper/strategy.py      маркет-мейкер
scalper/risk.py          pre-trade проверки и kill switch
scalper/oms.py           ордера
scalper/portfolio.py     позиция и PnL
scalper/features.py      онлайн-волатильность и поток сделок
scalper/orderbook.py     стакан, microprice, дисбаланс
scalper/marketdata.py    WebSocket-фид, запись, повтор, синтетика
scalper/gateways/        paper (симулятор) и live (ccxt)
scalper/backtest.py      бэктест и отчёт
scalper/telegram.py      уведомления и команды
```
